# 07. ロードマップ

## Phase 0 — 仕様確定 ✅

- PRD 一式と grill による主要論点の決着（[`_grilling/decisions.md`](./_grilling/decisions.md)）。
- エンコード条件の実測検証（[`_grilling/measurements.md`](./_grilling/measurements.md)）。
- 確定: アーキ / 標準条件 / 画像配信 / 得点式 / セッションの形。

## Phase 1 — MVP

**「1 人でひととおり遊べて、記録が残り、後から分析できる」まで。**

1. **`quiz-core`**（モード抽象・出題選択・採点・得点計算・Zod スキーマ）と単体テスト。
   **フレームワーク非依存**を保つ（[02](./02-architecture.md) §4-1）。
2. **コンテンツパイプライン**（`pnpm quiz:build`）。20 プロファイルでエンコードして実測。
   **問題 50 問程度**から始める。
3. Next.js + MySQL でセッションと採点（[04](./04-session-and-integrity.md) §2）。
4. 出題 → 回答 → **正解画面**（PNG/JPEG 両方の実物 + 20 プロファイルの結果 + 問題別正答率）。
5. 標準条件の明示ページ / プロファイル選択 UI。
6. サプライザル得点 / ランキング / 結果画面の統計（パーセンタイル・分布）。
7. **回答ログの完備**（[03](./03-data-model.md) §7）。可視化より先にログ。
8. R2 へのアセット同期（`pnpm quiz:upload`）。
9. **劣化の検証ビュー**（[04](./04-session-and-integrity.md) §4.1）。
   パイプラインでオーバーレイを事前生成し、正解画面で ΔE00 / SSIM を切り替える。
   設計原則 5「回答後は全部見せる」の実装であって、遊べる状態の前提条件ではない。
10. **クレジット一覧ページ**（[05](./05-content-pipeline.md) §1.4）。

### 🔒 公開（デプロイ）の前提条件

**開発中は配布していないので発生しない義務が、公開した瞬間に発生する。**
デプロイ前に必ず確認する:

- 🔒 **帰属義務のある素材（CC BY / CC BY-SA）が出題プールに残っていないこと。**
  帰属には原本への到達手段が要り、それがあると回答前に素性を割り出せる（T7）。
  義務と T7 は同じ素材の上では両立しない（[05](./05-content-pipeline.md) §1.1, §1.4）。
- **クレジット一覧ページがあること。** 素材の由来と AI 生成の別を**集合として**開示する。
  🔒 個別の帰属・サムネイル・出典リンクは載せない（[05](./05-content-pipeline.md) §1.4）。
- **素材のライセンスが全件確定していること。** 「要確認」が残ったまま公開しない。
- **フォトリアルな人物画像が含まれていないこと**（[05](./05-content-pipeline.md) §1.2）。
- **AI 生成である旨が回答後に開示されること**（出題前には出さない。§1.3）。

### Phase 1 で必ず守ること

- 🔒 出題レスポンスに**答えの方向を示す値を一切含めない**（[04](./04-session-and-integrity.md) §3.5）。
- 🔒 `display` は**可逆 WebP**。PNG を直に配らない。
- ⚠ パイプラインで `sharp.png()` の **`effort` を明示**する（[01](./01-quiz-domain.md) §3.3）。

### 遊んでから見直すもの（暫定値）

- 制限時間 20 秒 / 1 セッション 30 問 / 難易度カーブの刻み / 静的難易度重みの係数。
- **違う問題構成・競技基準を思いついたら足せる**ように `quiz-core` のモード抽象を保つ。

## Phase 2 — 深掘り

- デイリーチャレンジ、結果共有ページ + OGP。
- **別モード**: endless（連勝）/ confidence（確信度つき log score）。
- 「際どい問題」の合成（[05](./05-content-pipeline.md) §4）で問題数を増やす。
- 運営分析の画面化（見たい指標が固まってから。[06](./06-ranking.md) §6）。
- **Vite + Hono 版**（`quiz-core` / `database` をそのまま共有）。

## Phase 3 — 自動化

- フリー素材集からの自動収集 → 問題生成（[05](./05-content-pipeline.md) §5）。

## 検討はするが今はやらないこと

- WebP / AVIF を含む 3 択以上への拡張（**別ゲームになる**。まず 2 択を完成させる）。
- 実務向けの「この画像はどの形式で出すべきか」総合判断モード。
