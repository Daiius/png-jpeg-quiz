# 04. セッションと対タンパ

「最低限の対タンパ性を持ちつつシンプルに」を具体化する。**どこまで守り、どこを諦めるかを先に書く**のが本章の役目。

---

## 1. 脅威モデル

守る対象は **①ランキングの信頼性** と **②プレイ体験（自分でズルできてしまうと面白くない）**。

| # | 攻撃 | 難易度 | 方針 |
|---|---|---|---|
| T1 | クライアントに載っている正解を読む | 誰でも | **完全に防ぐ**。正解はサーバのみ（§2） |
| T2 | 出題画像の転送バイト数から答えを推測する | 開発者ツールを開くだけ | **易問のみ許容**（§3。実測に基づく判断） |
| T3 | 画像を保存して**自分でエンコードして調べる** | 手間はかかるが確実 | **原理的に防げない**。時間制限で割に合わなくする（§5） |
| T4 | 採点/スコア API を直接叩いて任意スコアを登録 | API を読める人 | **防ぐ**。スコアはサーバ計算のみ（§2） |
| T5 | 総当たり（同じ問題を何度もやり直して正解を覚える） | 誰でも | **緩和**。1 セッション内 1 回・毎回サーバ抽選（§2, §5） |
| T6 | bot による大量プレイ / 表示名の悪用 | 中 | **緩和**。レート制限・最短回答時間・表示名の検証（§5, §6） |
| **T7** | **得点の重みや統計から答えの方向を逆算する** | **誰でも** | 🔒 **設計で潰す**（§3.5）。**このアプリ固有で最も見落としやすい** |

> 🔒 **明示する線引き**: 本気で解析する人は排除しない。狙いは
> **「カジュアルなズルが成立しないこと」と「スコアの偽装ができないこと」**。

## 2. サーバ権威（T1 / T4 / T5）

- **正解・両形式のバイト数・`png`/`jpeg` アセットの URL は、回答を受け取るまで一切送らない。**
  出題レスポンスに含めるのは `display` の URL・寸法・カテゴリ表示だけ（[02](./02-architecture.md) §4-2）。
- **次の問題を決めるのはサーバ**。セッション開始時に全問を確定して渡さない
  （渡すと `question_id` の一覧が手に入り、事前に照会される）。
- **スコア・連勝はサーバが計算した値だけを保存**する。クライアントから送るのは
  「どちらを選んだか」のみ。経過時間もサーバの `served_at` 基準（[03](./03-data-model.md) §7）。
- **セッションの所有証明**: `session.id`（URL 用）と `secret`（HttpOnly / SameSite=Lax Cookie）を分ける。
  回答 POST は Cookie の `secret` を検証する。**署名付きステートレストークンは採らない**——
  DB 行があるほうが、再送防止・重複出題防止・不正検知の記録がそのまま書ける。
- **プロファイルはセッション開始時に固定**する。途中で変えられない（有利な条件への乗り換えを防ぐ）。
- **正解の偏りを出題側で補正する必要はない。** サプライザル得点が偏りを吸収するため
  （[06](./06-ranking.md) §1）。むしろ偏りは戦略性として機能する。

## 3. 出題画像からの漏洩（T2）

**問題文＝画像そのもの**なので、出題のために画像を配らざるを得ない。
そのレスポンスのバイト数がヒントになる。

### 3.1 決定: 可逆 WebP をそのまま配る

- `display` は**可逆 WebP**。**パディングはしない**。
- 🔒 **PNG を直に配ってはいけない**（`png_bytes` がそのまま見える）。この一点だけは絶対。

### 3.2 判断の根拠（実測）

「可逆 WebP のバイト数と、画面から見積もった JPEG サイズを比べる」戦略の的中率は **24/27（89%）**。
ただし**外れた 3 件はいずれも拮抗問題**だった（→ [measurements](./_grilling/measurements.md) §4）。

| 素材 | 可逆 WebP | PNG | JPEG |
|---|---|---|---|
| ピクセルアート | **280** | 1,111 | 5,596 |
| 8 色 UI | **3,772** | 4,414 | 72,889 |
| ゲーム系ツリー画面（拮抗） | 110,058 | 106,909 | 126,970 |

→ **易問は取られるが、難問では漏れない。** パディングのコストに見合わないと判断した。

### 3.3 将来パディングを入れる場合の注意

- ⚠ **ゼロ埋めは無意味**。`Content-Encoding: br` で潰れて元サイズが漏れる。**ランダムバイトで埋める**。
- ⚠ **パディングは剥がせる**。末尾チャンクを削れば元サイズが復元するので、
  「PNG にパディング」は意味がない。**原理的に情報ゼロにできるのは非圧縮ラスタだけ**。
- パディングはビルド時にファイルへ焼く（配信側の細工は不要）。

### 3.4 URL からの漏洩

- 🔒 **回答前に `png` / `jpeg` の URL を渡さない。** URL があれば HEAD リクエストで答えが取れる。
- 🔒 **渡さないだけでは不十分。パスが推測できてはいけない。**
  `display` と同じ階層や、`question_id` / `profile_id` から組み立てられる固定パスに置くと、
  出題時に得た情報だけで回答用アセットに直接到達できる。
  → **キーは暗号学的乱数**にして DB だけが対応を持つ（[03](./03-data-model.md) §5.2、
  [05](./05-content-pipeline.md) §2）。
- ⚠ **内容ハッシュをキーにするのも不可。** 出題画像は可逆 WebP なのでピクセルを完全に復元でき、
  同じ手順で PNG を作ればハッシュを計算できる。「推測不能」には**ハッシュでは足りない**。
- **URL やファイル名にバイト数・元ファイル名・プロファイル名を含めない。**

### 3.5 🔒 得点・統計からの漏洩（T7）

**最も見落としやすい経路。** 判断基準は「その情報が**対称か非対称か**」:

| 情報 | 対称性 | 扱い |
|---|---|---|
| プロファイル全体の答えの偏り | 個別問題について何も語らない | ✅ 公開してよい（戦略性になる） |
| 静的難易度（サイズ比の拮抗度） | 「拮抗」と分かってもどちらが勝つかは決まらない | ⚠ **数値は回答前に見せない** |
| **実測正答率** | 「みんなが間違える」＝「**直感と逆が正解**」が一意に決まる | ❌ **得点に使わない・回答前に到達させない** |
| **素材の素性（出典・AI 生成の別）** | 素性ごとに答えが極端に偏る（下記） | ❌ **回答前に出さない** |

⚠ **出典と「AI 生成」の表示は漏洩経路になる。** 実測では AI 生成 18 点が 360 通り中 PNG 勝ち 8 通り
（2.2%）、Wikimedia Commons のベクタ由来 2 点が 40 通り中 27 通り
（→ [measurements](./_grilling/measurements.md) §7.4）。**出題画面に「AI 生成」と出すのは
「JPEG と答えろ」と言うのに等しい。** ライセンス上の帰属義務とは衝突しないよう、
**回答後の画面とクレジット一覧ページに置く**（→ [05](./05-content-pipeline.md) §1.3）。

**具体的な禁止事項**:

- 🔒 出題レスポンスに `difficulty` / `log2_ratio` / 得点の重みを含めない。
- 🔒 **問題別の正答率を、回答前に到達できる場所に置かない。** 統計ページで
  「正答率が低い問題ランキング」を公開すると、その問題に当たった人が「直感と逆」と分かる。
  公開する場合は**問題を特定できない集計（分布のみ）**にする。
- 🔒 実測正答率を静的難易度に混ぜない（混ぜると難易度経由で漏れる）。
- ⚠ 難易度カーブに沿って出題する時点で「後半ほど難しい」は開示されている。
  これは体験のために許容するが、**数値としては伏せる**。

## 4. 正解画面（意図的に「開けて確かめられる」ようにする）

回答後は、逆に**全部見せる**。ここは対タンパの対象外——むしろ検証可能性が売り。

- PNG / JPEG **両方の実物を表示**し、それぞれのバイト数を数値で併記する。
- 開発者ツールの Network タブで**実際の転送サイズを確認できる**状態にする。
- **20 プロファイルすべての結果**（この画像は q60 では JPEG、q95 では PNG が勝つ、等）。
- **この問題の実測正答率**（「78% が間違えています」）。回答後なので開示してよい。
- 標準条件（[01](./01-quiz-domain.md) §3）へのリンク、拡大比較、出典・ライセンス。
- 「僅差なら劣化・透過・用途で決めるべき」という注意（[01](./01-quiz-domain.md) §6）。

## 5. 時間制限とレート制限（T3 / T5 / T6）

- **1 問 20 秒**（30 問で最大 10 分）。**暫定値、遊んでから調整する**。
  ローカルでエンコードして調べる余裕を無くすのが主目的。時間切れは不正解扱い。
- **最短回答時間の下限**（例: 300ms 未満は無効）。人間に不可能な速さを弾く。
- IP / セッション単位のレート制限（セッション作成・回答）。
- 異常なパターン（全問正解かつ全問 1 秒未満など）は `score_entry.flagged` を立て、
  **ランキングから除外するが本人には見せる**。

## 6. 表示名（T6）

- ランキング登録時のみ入力。長さ制限・制御文字/不可視文字の除去・NFKC 正規化。
- 出力は必ずエスケープ（React 既定で足りるが、OGP 画像生成側でも要注意）。
- 不適切語フィルタは MVP では最小限。

## 7. 諦めるもの（明記しておく）

- **T3（自分でエンコードして調べる）は防げない。** 時間制限で割に合わなくする以上のことはしない。
- **T2 の易問は取られる**（§3.2）。難問で漏れないことを確認したうえでの割り切り。
- 認証がない以上、**同一人物が何度も登録すること自体は止められない**。
