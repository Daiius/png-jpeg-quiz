# 06. 得点・ランキング・分析

得点式と記録の設計。データ構造は [03](./03-data-model.md)、漏洩の制約は [04](./04-session-and-integrity.md) §3.5。
設計の経緯は [`_grilling/decisions.md`](./_grilling/decisions.md) §2.4〜2.6。

## 1. 得点式（サプライザル方式）

```
得点 = Σ [ 正解 × 静的難易度重み(question) × ( -log2( p_profile(その問題の答え) ) ) ]
```

- **`p_profile(answer)`** = そのプロファイルの**問題プール全体**で、その答えが占める割合。
  `encode_profile.png_win_rate` から求める（[03](./03-data-model.md) §2）。
- **静的難易度重み** = `|log2_ratio|` から算出した値（拮抗しているほど大きい）。
  🔒 **数値は回答前に見せない**（[04](./04-session-and-integrity.md) §3.5）。
- 不正解・時間切れは 0 点。

### なぜこの形か

**条件選択とランキングの両立**が目的。プロファイルを自由に選べるので、
「有利な条件を選んで稼ぐ」抜け道を塞ぎつつ、**選ぶ動機は残す**必要があった。

- q60（PNG 勝ち 30%）で JPEG を当てても `-log2(0.7) = 0.51` 点。
- しかし **PNG を見抜けば `-log2(0.3) = 1.74` 点**。
- 期待値はエントロピー `H(p)` なので **50:50 の標準条件が最大**。偏った条件は期待値が低い代わりに**分散が大きい**。

→ **偏った条件はハイリスク・ハイリターン**。30 問あるので分散は均され、
平均的には標準条件が有利。それでも「自分は少数派を見抜ける」人には上振れの余地がある。
**条件が違っても 1 本のランキングに混ぜられる。**

### 🔒 実測正答率を得点に使わない

一度「`p` を実測正答率にすれば難易度推定と得点式が一本化されて美しい」と設計したが、**誤りだった**。
二択では「みんなが間違える」＝「**直感と逆が正解**」が一意に決まり、得点の重みが答えの方向を指す。

- **使ってよいのは対称な情報だけ**（プロファイル全体の偏り / サイズ比の拮抗度）。
- 実測正答率は**非対称**なので、運営分析と回答後の表示に限定する。
- 詳細は [04](./04-session-and-integrity.md) §3.5。

### 検討したが採らなかったもの

- **時間ボーナス**: 二択なので「当てずっぽうで即答」が最適戦略になりかねない。入れない。
  経過時間はログに残すだけ（[03](./03-data-model.md) §7）。
- **確信度つき採点（log score）**: 二択の情報量不足を根本から解く優れた方式だが、UI が複雑。
  同じ proper scoring rule なので、**モードの差し替えだけで後から載る**（§2）。

## 2. モードとプロファイル

| | MVP | 内容 |
|---|---|---|
| **`standard-30`** | ✅ | **30 問固定**。難易度カーブに沿って出題。プロファイル選択可 |
| `endless` | Phase 2 | 不正解まで。記録は連勝数。**問題プールの深さが要る** |
| `confidence` | Phase 2 | 確信度つき予測。`log2(q)+1` で採点 |

- モードは `quiz-core` の抽象（[02](./02-architecture.md) §4-1）。**遊んでから思いついた基準を足せる**。
- **プロファイルはセッション開始時に固定**（[04](./04-session-and-integrity.md) §2）。

### なぜ 30 問か

⚠ **二択 × 10 問では実力差が出ない。** 実力 80% の人が 10 問全問正解する確率は **10.7%** で、
100 人遊べば 10 人が満点になりランキングが機能しない。20 問で 1.2%、**30 問で 0.12%**。
加えて 30 問あることで、偏った条件を選んだときの得点減が積み上がり、§1 のトレードオフが成立する。

## 3. ランキング

- 掲載単位は `score_entry`（セッション確定時のスナップショット。[03](./03-data-model.md) §9）。
- ビュー: **全期間 / 今日**、および参考として最長連勝。
- **プロファイルが違っても同じランキング**（サプライザル正規化）。使った条件は表示する。
- 表示名は任意入力（[04](./04-session-and-integrity.md) §6）。未入力なら匿名として集計のみ。
- `flagged` は集計から外すが、本人の画面では通常どおり見える。

## 4. 結果画面の統計

プレイヤーに見せるもの。**問題を特定した正答率は、回答後にのみ出す**。

| 表示 | 内容 | 漏洩 |
|---|---|---|
| パーセンタイル | 「上位 23%」 | 問題を特定しないので安全 |
| 得点分布 | 全プレイのヒストグラム上に自分の位置 | 同上 |
| **問題別の正答率** | 「この問題は 78% が間違えています」 | **回答後なので安全**。⚠ 統計ページには出さない |
| 20 プロファイルの結果 | この画像は q60 では JPEG、q95 では PNG | 回答後なので安全 |

## 5. 共有（Phase 2）

- 結果ページ `/r/<session_id>`（read-only）と OGP 画像。Next.js の Server Components で生成する。
- 共有カードに載せるもの: モード・条件・スコア・正答率。
  🔒 **問題の正解は載せない**（未プレイの人へのネタバレ・漏洩になる）。

## 6. 分析（運営）

**MVP はログ完備 + SQL / スクリプト。** 可視化は見たい指標が固まってから作る
（[03](./03-data-model.md) §7 に全回答が残るので、集計は後から何でもできる）。

見たい指標:

| 指標 | 用途 |
|---|---|
| 問題別の正答率（プロファイル別） | **みんなが間違える問題の把握**。素材選定の質 |
| 静的難易度と実測正答率の**乖離** | 「拮抗していないのに全員間違える」＝ 直感と逆行する良問の発見 |
| プロファイル別のプレイ数・スコア分布 | 条件選択が機能しているかの検証 |
| 何問目で離脱するか | 30 問が長すぎないかの判断（[04](./04-session-and-integrity.md) §5 の暫定値の見直し） |
| 回答時間の分布 | 制限時間 20 秒の妥当性 |

- ⚠ **実測正答率を難易度に反映するかは慎重に。** 反映すると難易度経由で答えの方向が漏れる
  （[04](./04-session-and-integrity.md) §3.5）。**現時点では反映しない**方針。
  「正答率が極端に低い問題を retire する / 出題頻度を下げる」といった**運営判断の材料**としてのみ使う。
