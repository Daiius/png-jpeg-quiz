# 08. ビジュアル設計（色・テーマ・幅）

> 画面の**見た目の規則**。画像の見せ方そのものは [01](./01-quiz-domain.md) §7、
> 何を出してよいかは [04](./04-session-and-integrity.md) §3.5 が正典で、ここはそれに従う。

## 0. なぜ規則が要るか

🔑 **この画面のデザインは、好みではなく成立条件から決まる。**
プレイヤーは画素の細部（ノイズ・平坦部・輪郭）を読んで判断する。UI がその観察を妨げたら、
それは装飾の問題ではなく**判断材料の劣化**になる。

以下の 4 つは、実画面を測って出てきた制約である。値を動かす前にここを読むこと。

| | 制約 | そこから決まるもの |
|---|---|---|
| 1 | 🔒 **UI は画像の見えに干渉しない** | 無彩色を基調にし、彩度を最小に保つ |
| 2 | 🔒 **素材はどんな色でも来る** | 状態を色だけで表さない。`wrong` は純赤を外す |
| 3 | 🔒 **出題中は 2 択が完全に対等** | 形式の識別色は回答後だけ |
| 4 | **数字が答えそのもの** | 等幅・`tabular-nums`・単位を落として組む |

### 1 の根拠

彩度のある面を画像の隣に置くと、**同時対比で画像の色が変わって見える**。
写真の展示で周囲を無彩色にするのと同じ理由。無彩色はアクセント（深い青緑）と同じ方向へ
ごくわずかに傾けてあるが、彩度は 1〜2% に留める。

### 2 の根拠

⚠ **素材の色は選べない。** 実際に 1 問目は赤ベタ（`#DF1C1F`）で、ここに `red-600` の
「不正解」を出すと**同じ画面で赤が二重になる**。だから:

- 正誤は**記号（○ / ✗）と文字**で表し、色は補助に留める。
- `--color-wrong` は**赤紫（`#A8324A`）**。純赤を避けることで素材と衝突しない。

### 3 の根拠

出題中に PNG / JPEG の色・面積・枠に差を付けると、**それ自体が答えの方向を示す手がかり**に
なりうる（[04](./04-session-and-integrity.md) §3.5）。2 択のボタンは完全に同じ見た目にする。
回答後は逆に、20 条件の表と検証ビューで識別が要るので、**そこで初めて**色を割り当てる。

## 2. 色トークン

🔒 **唯一の正は `packages/web/app/globals.css` の `@theme`。** TSX に生の色を書かない
（`slate-600` / `bg-white` / `text-red-700` などを直接使わない）。

### 2.1 無彩色（6 段 + 面 2 つ）

役割で呼ぶ。**階調の番号では呼ばない**（`--color-slate-600` のような名前にしない）。

| トークン | 用途 |
|---|---|
| `--color-ground` | ページの地 |
| `--color-surface` | 囲み・カード・ボタンの面 |
| `--color-sunken` | 画像の台・折りたたみの中・強調行 |
| `--color-line` | 通常の罫 |
| `--color-line-strong` | 画像の境界・ボタンの枠 |
| `--color-ink-faint` | 単位・補助ラベル |
| `--color-ink-muted` | 説明文 |
| `--color-ink` | 本文・見出し・数値 |

### 2.2 形式の識別（🔒 回答後だけ）

`--color-png` / `--color-jpeg`。**常に「PNG」「JPEG」の文字を併記する**（色だけで区別しない）。

### 2.3 状態

`--color-correct` / `--color-wrong` / `--color-caution`。
🔒 **色だけに意味を持たせない。** 記号（○ / ✗ / ⚠）と併用する。

### 2.4 暗室（拡大ダイアログ）

`--color-darkroom` / `--color-darkroom-ink` / `--color-darkroom-line`。

🔒 **ライト・ダークのどちらでも暗いまま。テーマに追従させない。**
拡大ダイアログは画素を観察するための面であり、明るい地に置くと**目が順応せず細部が見えない**。
写真の暗室と同じ理由で、ここだけは環境から独立させる。

## 3. テーマ

**ダークは OS 追従のみ**（`prefers-color-scheme`）。**トグルは持たない。**

- 🔑 画像を観察するアプリなので、暗い地のほうが素材は正しく見える。
- ⚠ **反転ではなく組み直し。** `--color-png` などは明度を上げないと暗地で沈む。
- ⚠ **面を持つ要素は UA 既定の背景（`canvas` = 白）を持つ。**
  `<dialog>` と `<select>` がこれに当たり、トークンを当てないとダークで白いまま浮く。
  **preflight 任せにしない。**

## 4. 幅の規則

🔒 **ブレークポイントは `lg`（1024px）1 本。**
`md`（768px）は `max-w-3xl` と同値で、境界として意味を持たない。

| 対象 | 幅 |
|---|---|
| **画像** | `max-w-3xl`（768px）の**パディング無しの列**。**原寸を超えない**（[01](./01-quiz-domain.md) §7.1）。⚠ **ブレークポイントを入れない** |
| **読み物**（説明文・ボタン・出典) | `max-w-3xl` + `px-6`（内寸 720px）で固定 |
| **データの面**（検証ビュー・20 条件の表） | `max-w-3xl lg:max-w-5xl` |

### 4.1 なぜ画像に幅の分岐を入れないか

🔑 **細部の観察は全環境でダイアログが担う**（2026-08-18 の 2c 反映）。
インラインの画像は「全体を見る」役に固定し、読み物と同じ列に収める。だから幅の分岐は要らない。

- ⚠ かつては「幅いっぱい＝倍率の最大値（1280px で原寸）」を根拠にデスクトップの
  インラインが細部を担っていたが、**この根拠ごと 2c で置き換えた**。
  代償としてインラインでは原寸に届かない素材が増えるので、
  **拡大導線と縮小率の注記を常設する**（[01](./01-quiz-domain.md) §7.1・§7.4）。
- モバイル（< 768px）の見え方は従来と変わらない（列にパディングが無いため端まで出る）。
  余る縦の使い方も §4.2 のまま。sticky ボタンも維持（列幅でも縦長素材でははみ出す）。

### 4.2 モバイルの余白は拡大導線に使う

[01](./01-quiz-domain.md) §7.4 の通り、**モバイルではダイアログが必須であって装飾ではない**
（幅いっぱいでも 0.30x にしかならず、インラインだけでは細部が見えない）。
にもかかわらず画像には「押せる」手がかりが要る。

- **画像の直後に拡大導線を置く。** 幅 390px では画像の下に約 300px が余るので、そこに収まる。
- ⚠ **画像の上に重ねない。** 制約 1（UI は画像の見えに干渉しない）に反する。
- 🔒 出してよいのは「拡大できる」ことだけ。**倍率も寸法も答えの方向を示さない**。

### 4.3 比較はレイアウトではなくダイアログが担う

回答後の PNG / JPEG は**縦積みのまま画像の列（§4）に収める**（[01](./01-quiz-domain.md) §7.1）。
横並びは各々が半分の幅になり、劣化が見えなくなる。

🔑 **同一視野に並べるより、[01](./01-quiz-domain.md) §7.3 の A/B 切替（倍率とスクロール位置を保持）
のほうが人間の目には差が見える。** 2 枚の比較で足りないのは**レイアウトではなく導線**なので、
「同じ位置で切り替えて比べる」ボタンを実物の直後に置く。
