## 測定条件

- `sharp 0.35.3` / `libvips 8.18.3` / `@jsquash/oxipng`（wasm）。Node 24。
- 素材 27 点: 実写 6（1024×768）/ 生成イラスト・UI・グラデーション / アニメ調 /
  フラット+微細ノイズ 3 段階 / 減色写真 3 / ぼかし写真 2 / グレースケール写真 /
  ゲーム UI スクショ 2 / 減色して「真にフラット」にしたもの 5 / ピクセルアート。
- 前処理: `flatten` → `removeAlpha`。原寸のまま（リサイズなし）。
- JPEG: `quality=q, chromaSubsampling='4:2:0', progressive=true, mozjpeg=true`。

## 1. ⚠ sharp の `png()` の落とし穴（実装時に必ず踏む）

同じ写真 1 枚（1024×768）:

| 呼び出し | バイト数 |
|---|---|
| `png()`（既定のまま） | 1,783,911 |
| `png({ compressionLevel: 9 })` | 1,678,028 |
| `png({ compressionLevel: 9, palette: false })` | 1,678,028 |
| **`png({ compressionLevel: 9, effort: 7 })`** | **415,817** |
| **`png({ compressionLevel: 9, effort: 10 })`** | **414,748** |

- **`effort` を明示しないと 4 倍のサイズになる。** `compressionLevel` はほとんど効かない。
- `palette: false` を明示すると `effort` の指定が無視される（明示しないのと同じ結果になる）。
- → パイプラインでは **`effort` を必ず明示**し、生成物のバイト数を CI で監視する
  （[05](../05-content-pipeline.md) §6）。

- `-o2` と `-o4` の差は 1〜6%。拮抗問題では効くので **`-o4` を標準**とする。

## 3. JPEG 品質と答えの分布

| JPEG 品質 | q60 | q75 | **q80** | q90 | q95 | q80(4:4:4) |
|---|---|---|---|---|---|---|
| PNG 勝率 | 30% | 41% | **48%** | 56% | 59% | 56% |

- **q80 / 4:2:0 が最も 50:50 に近い**。→ 標準プロファイル `std-v1` の根拠。
- 27 素材のうち **8 件が q60 と q95 の間で答えが反転**する（UI スクショ / グラデーション /
  フラット+ノイズ / 減色写真 など）。→ **[06](../06-ranking.md) のプロファイル選択に意味がある根拠。**

## 4. 配布サイズからの漏洩（可逆 WebP で配る場合）

「可逆 WebP のバイト数と、画面から見積もった JPEG サイズを比べる」戦略の的中率: **24/27（89%）**。

| 素材 | 可逆 WebP | PNG(oxi -o4) | JPEG q80 |
|---|---|---|---|
| ピクセルアート | **280** | 1,111 | 5,596 |
| UI 8色 | **3,772** | 4,414 | 72,889 |
| フラットイラスト | 7,936 | 7,856 | 16,011 |
| ゲーム系ツリー画面 | 110,058 | 106,909 | 126,970 |
| 実写 1 | **881,972** | 383,968 | 150,899 |

- **易問（極端な画像）は WebP のバイト数だけでほぼ判定できる。**
- 外れた 3 件は `フラット+ノイズ(amp4)` / `減色写真(16色)` / `アニメ調`——
  **いずれも作りたい拮抗問題**。難問では漏れない。
- → この分布を根拠に、**パディングせず可逆 WebP をそのまま配る**と決定
  （[04](../04-session-and-integrity.md) §3）。

## 5. リサイズは PNG を不利にする

長辺 1024 / 512 / 256 に縮小して測ったところ、**512・256 では 27 件すべてが JPEG 勝ち**になった。

- 縮小時の再サンプリング（Lanczos）で中間色が大量に生まれ、色数が増えて PNG が不利になるため。
- → **パイプラインで安易にリサイズしない**。素材は原寸で扱い、寸法を変えるなら
  「意図した加工」として `derivation` に記録する（[05](../05-content-pipeline.md) §4）。
